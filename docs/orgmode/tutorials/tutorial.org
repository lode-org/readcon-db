In this lesson you build a corpus from three small files in the plain-text structure format (CON).
You then filter the corpus by element, forces, atom count, and energy.
Last, you read one frame back and find a repeated trajectory by its content hash.
The commands use the =readcon-db= command-line tool and the input files under =resources/test/= in the repository.
Each output block on this page comes from =docs/orgmode/tutorials/tutorial-run.log=, which =docs/orgmode/tutorials/tutorial-run.sh= writes by running the same commands.

** Before you start
:PROPERTIES:
:CUSTOM_ID: before-you-start
:END:
You need =git= and a Rust toolchain with =cargo=.
Clone the repository, build the tool, and put it on your command search path (=PATH=):

#+begin_src sh
git clone https://github.com/lode-org/readcon-db
cd readcon-db
cargo build --release
export PATH="$PWD/target/release:$PATH"
#+end_src

Stay in the =readcon-db= directory for the rest of the lesson, because every input path below starts there.

** Ingest three files
:PROPERTIES:
:CUSTOM_ID: ingest
:END:
Create a corpus called =tutorial.db= from three files:

#+begin_src console
$ readcon-db ingest tutorial.db resources/test/tiny_multi_cuh2.con resources/test/sulfolene.con resources/test/tiny_cuh2_forces.con
traj 1: 2 frames from resources/test/tiny_multi_cuh2.con
traj 2: 1 frames from resources/test/sulfolene.con
traj 3: 1 frames from resources/test/tiny_cuh2_forces.con
#+end_src

Each file became one trajectory, numbered from 1 in the order you listed them.
The first file has two frames of two copper and two hydrogen atoms.
The second has one 13-atom sulfolene molecule.
The third has one frame of the same four atoms with forces and an energy.

The corpus is a directory with one Lightning Memory-Mapped Database (LMDB) environment in it:

#+begin_src console
$ ls tutorial.db
data.mdb
lock.mdb
#+end_src

=data.mdb= keeps the compressed CON text of every frame and the indexes built from it.
Many processes can read it at once, and one process writes at a time.

** Select frames
:PROPERTIES:
:CUSTOM_ID: select
:END:
Ask for every frame that contains copper:

#+begin_src console
$ readcon-db select tutorial.db --symbol Cu
3 keys
  traj=1 frame=0
  traj=1 frame=1
  traj=3 frame=0
#+end_src

A key names one frame by its trajectory and its position in that trajectory.
=select= answers from the symbol index and decodes no frame.

Filters combine.
Of those three frames, only the one from the third file has forces:

#+begin_src console
$ readcon-db select tutorial.db --symbol Cu --require-forces
1 keys
  traj=3 frame=0
#+end_src

Atom count and energy have their own indexes.
The sulfolene frame is the only one with 10 or more atoms, and the frame from the third file is the only one that records an energy (-42.5):

#+begin_src console
$ readcon-db select tutorial.db --natoms-min 10
1 keys
  traj=2 frame=0
$ readcon-db select tutorial.db --energy-max 0
1 keys
  traj=3 frame=0
#+end_src

A frame with no energy matches no energy filter.

** Read a frame back
:PROPERTIES:
:CUSTOM_ID: read-a-frame-back
:END:
Print the positions of the first frame of trajectory 1:

#+begin_src console
$ readcon-db positions tutorial.db --traj 1 --frame 0
traj=1 frame=0 natoms=4 valid_cooked=false
  [0] 0.6394 0.9045 6.9753
  [1] 3.1969 0.9045 6.9753
  [2] 8.6823 9.947 11.733
  [3] 7.9421 9.947 11.733
#+end_src

These are the coordinates in =resources/test/tiny_multi_cuh2.con=, parsed from the stored CON text.
~valid_cooked=false~ means the frame has no optional cooked numeric copy, which is the default after ingest.

** Find a repeated trajectory
:PROPERTIES:
:CUSTOM_ID: find-a-repeated-trajectory
:END:
Ingest the first file again.
Trajectory 1 already exists and =ingest= refuses to overwrite it, so give the copy a new number with =--start-id=:

#+begin_src console
$ readcon-db ingest tutorial.db --start-id 10 resources/test/tiny_multi_cuh2.con
traj 10: 2 frames from resources/test/tiny_multi_cuh2.con
$ readcon-db select tutorial.db --symbol Cu
5 keys
  traj=1 frame=0
  traj=1 frame=1
  traj=3 frame=0
  traj=10 frame=0
  traj=10 frame=1
#+end_src

The copy under trajectory 10 gives the corpus two copies of the same two frames.
Each stored frame carries an xxHash3-128 hash of its CON text, and =dedup-export= keeps the first frame stored under each hash:

#+begin_src console
$ readcon-db dedup-export tutorial.db --symbol Cu -o copper.xyz
3 keys
wrote 3 frames -> copper.xyz
#+end_src

Under those hashes the five copper frames came out as three, because trajectory 10 repeats trajectory 1 exactly.
=copper.xyz= is an extended =xyz= file for tools that read that format.

When you are done, remove the corpus and the export:

#+begin_src console
$ rm -r tutorial.db copper.xyz
#+end_src

** What you did
:PROPERTIES:
:CUSTOM_ID: what-you-did
:END:
You built a corpus from three CON files and selected frames by element, forces, atom count, and energy without decoding any of them.
You printed one frame's coordinates and found a repeated trajectory by content hash.
